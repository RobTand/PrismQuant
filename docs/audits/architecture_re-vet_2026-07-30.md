**What this is.** The re-vet Robert asked for after the docs consolidation: *"re-vet the architecture and see if there are any fundamental changes we want to make; make sure we're using our plugin architecture right and using configurations for supporting individual models."* Six lenses (cost/allocation, pipeline, plugins, lanes, validation, de-scope) verified every claim in code at `ef50495` and wrote proposals, not patches. **No code and no docs were changed.**

## Executive summary

The architecture is **sound**. Four of six lenses returned an explicit null on their own core: the cost family, the solver, the orchestrator, the metric hierarchy, the three-registry plugin design and the format menu need no fundamental change, and cross-layer modelling stays buried. Every real finding sits in one of three places — **selection** (the ship decision still runs on the surrogate), **provenance** (artifacts do not record what produced them), and **wiring debt of one repeating shape** (a declarative extension point defined, parsed, documented, with no production caller). The de-scope lens found the inverse of over-engineering: ~15k lines (21% of `prismaquant/`) implement two cost-cascade levels and a contract layer the pipeline never runs. The decisions that matter most: **(1)** make the byte budget the constraint and measured KL the objective, retiring kneedle to diagnostic (R1); **(2)** flip `COST_MODE=aura` to default, gated on a cost-provenance stamp that stops silent stale-table reuse (R2); **(3)** decide whether CB is *a* lane or *the* lane by funding the `col_weights` render identity that lifts its cost/selection gates (R3); **(4)** retire the L1/L2/L3 cascade framing from the spine — it has no executor, no consumer and a null result (R4); **(5)** rule on `pipeline.py` — settings-hash authority or linter-or-gone, where two lenses disagree (R5).

## Lens 1 — cost models, allocation, selection

*§2, §4, D1/D12.* **Null where it matters:** the *math* needs no fundamental change. The cost family (additive KL-Fisher × rendered dW), the collapse of L1/L2/L3 to one level, and the solver (serving-atomic DP unit, feasible-only termination, memoized ratchet) are sound and code-backed. **Every real gap is in the selection layer and in cost provenance, not in the estimator.**

### R1 (L1 P1) — Byte budget = constraint, measured KL = objective; kneedle → diagnostic · FUNDAMENTAL

**What.** Two disjoint ship selectors exist. (i) `allocator.py --target-disk-gb` (`:1202`, impl `:2276-2605`) uses exact footprint as the feasibility gate then picks by **predicted** Δloss — objective stamped `min_predicted_dloss__ties_to_larger_footprint` (`:2288`). (ii) `select_validated_frontier.py` picks by **measured** KL but is byte-blind: `grep -c 'bytes\|disk_gb'` → 0, and `measured_rows` (`:170-207`) whitelists only kl/bpp/format_counts/changed_vs_base/mse/surrogate_loss. The selector that owns the ship decision runs on the surrogate; the one that measures cannot see the card — §2.2 inverted exactly where it is load-bearing. Proposal: one stage. Plumb `TARGET_DISK_GB` into `run-pipeline.sh` (closes D12); convert budget → max body-bpp via `footprint.floor_bytes_for_model` (bytes are affine in body bpp at fixed model — exact, not a fit); add a `budget` pick = **min measured KL among rows that fit**; keep kneedle as the diagnostic `_rd_curve_diagnostic` (`allocator.py:285-338`) already says it is. Side effect that pays for the whole thing: the budget bracket collapses the Pareto set from 11 rungs (`run-pipeline.sh:47`) to the ~3 that can fit.

**Why now.** The surrogate-knee failure is on record (§11: 27B surrogate 5.857/0.056 vs validated 5.31/0.015) *and* the RD diagnostic already prints "select ship bpp by byte budget or measured saturation, not curvature" (`allocator.py:329-334`) — code telling the operator to do what the pipeline cannot. Every byte-budget ship to date is a manual CLI invocation (D12).

**Cost** M. **Risk** none while `VALIDATED_FRONTIER_PICK=kneedle` and `TARGET_DISK_GB` unset — both paths opt-in, byte-identical when off; the risk lives entirely in the default flip.

**Verdict-request.** (a) Should `TARGET_DISK_GB`, when set, override `TARGET_BITS` in the pipeline as it does in the CLI? (b) Should `validated-surrogate` default **on only under a byte budget** (~3 KL evals), staying opt-in for open-ended `TARGET_BITS` runs? Lens recommends yes to both. *Corollary:* do **not** promote `validated-surrogate` unconditionally — alone it turns the assignment-scope render (`run-pipeline.sh:177`) into a format-menu render (`:1153-1170`), ~2× render on a 3-format menu, plus 11 KL evals, to decide a bpp a byte budget fixes for free.


**Outcome: ACCEPTED, implemented 2026-07-30 — both verdict-requests answered YES by Robert.**
(a) `TARGET_DISK_GB`, when set, **overrides `TARGET_BITS`** in the pipeline exactly as it does
in the CLI. (b) `validated-surrogate` defaults **on only under a byte budget**, staying opt-in
for open-ended `TARGET_BITS` runs — an explicit `SELECTION_MODE` still wins. Mechanism: the
allocator prices every Pareto candidate with `footprint.assignment_artifact_bytes` (the same
accounting its own byte-budget selector uses) and stamps `artifact_bytes` into each assignment
payload + the manifest; under a card it narrows the Pareto set to the largest fitting rung ±1
(~3 of 11) with a log line — a computed narrowing, skipped loudly if any candidate is unpriced;
`select_validated_frontier --mode budget --target-disk-gb` picks **min measured KL among the
rows that fit**, reading the bytes column from the allocator payload. Unpriced rows and an
infeasible card are hard errors, never a silent fall-back to another pick. Kneedle stays the
default without a card and stays the diagnostic `_rd_curve_diagnostic` already calls it.
Byte-identical when `TARGET_DISK_GB` is unset (pinned by a test). Closes **D12**.

### R20 (L1 P4) — CB ladder law: no served A/B warranted; unify the chains, derive the tolerance · STRUCTURAL

**What.** The split-aware floored law is the right family, and "+14.2% on exact-exponential data" is not an argument against it. (1) **The holdout gate arbitrates accept/reject of one law, not a bake-off.** `_ladder_metric_fit` (`measure_quant_cost.py:1621-1671`) returns from branch 1 (floored linear in `R(k)`) whenever `C > 0`; branches 2/3 are reached only on non-monotone/degenerate anchors. On the unit test's free-rate exponential the fit misses the holdout by 31% against `_CB_LADDER_TOL = 0.10`, the tensor is rejected, and the predicted rungs are **measured** (`:2002-2007`; test `tests/test_measure_quant_cost_packed_experts.py:377-381`). The law's only material cost is encode wall-time, not shipped cost fidelity.
